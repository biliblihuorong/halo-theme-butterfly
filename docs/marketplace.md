本主题不要求安装 ImgNest，未使用图床预览时可按普通 Halo 主题使用。ImgNest 生态关系、维护者相同、提交数量或主题标识冲突，都不能单独证明独立上架的必要性。

本分支拟申请的定位是：在 Butterfly 视觉基础上，组合维护访客阅读工具、Artalk / Umami 适配、图片加载策略和多插件页面，并提供相应的配置迁移与发布验证。审核材料应结合上表说明这些功能的实际使用场景，同时先向上游贡献通用改进。独立标识用于隔离安装、配置和更新渠道，是技术措施；独立上架仍需由市场结合贡献记录、实际差异与维护安排评估。

## 后续维护计划

维护流程以可复现问题和可核验制品为依据，不预设固定发版周期或响应时限：

1. 通过[本项目 Issue](https://github.com/biliblihuorong/halo-theme-butterfly/issues)收集主题、Halo、插件、浏览器版本与复现步骤；区分主题故障、插件契约变化和站点配置。
2. 通用问题优先评估向上游贡献；涉及本分支专属配置和可选集成的改动，记录适用范围。跟进上游新提交时评估合入及冲突，不以最后提交日期替代兼容性检查。
3. 发布前执行项目要求的回归测试、完整构建和 ZIP 校验，再由维护者完成主要路径人工验收。新增 Halo / 插件支持范围须有相应测试记录；未验证版本不写成已验证兼容。
4. 每次发布同步版本、安装包、版本说明与迁移 / 回退要求；保留历史版本及校验文件，不用相同版本号替换不同内容的安装包。市场页面使用相同版本和本项目图标。
5. 若以后无法持续维护，先公开说明实际状态与用户的保留版本、备份和迁移方式，再评估协作维护安排；不提前声称获得上游支持。
