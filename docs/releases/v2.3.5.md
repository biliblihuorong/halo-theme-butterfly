# Butterfly-shell v2.3.5

本版修复预览图模式下响应式插件写入的真实封面候选被清除的问题，更新本项目图标与社区身份说明，并补齐派生来源、安装、配置迁移和回退材料。

Butterfly-shell 是由 shell 维护的社区派生版本，不代表 Halo 官方、上游 Halo 移植版维护者或 Hexo Butterfly 原作者。来源、差异和上游贡献的实际状态见[派生与应用市场说明](https://github.com/biliblihuorong/halo-theme-butterfly/blob/v2.3.5/docs/marketplace.md)。

## 改进与修复

- **响应式封面**：在 `src` 暂为占位图、真实地址位于 `data-lazy-src` 时，若插件通过 `data-responsive-src` 标明候选属于同一真实图片，保留其 `srcset` 并使用浏览器原生选图。缺少匹配标记的占位图候选仍会移除；真实候选失败时仍撤下 `srcset` 后重试原图，再失败才显示错误占位图。对应修复为 [`7f15c5a`](https://github.com/biliblihuorong/halo-theme-butterfly/commit/7f15c5a)。
- **项目图标与身份**：主题元信息使用本项目的蝴蝶图标，简介和文档明确社区派生身份。应用市场端重新提交时需上传 `src/img/logo.png`（512 × 512），与主题包中的 PNG 保持一致；仓库内整改不表示市场图标已经同步。
- **派生材料**：记录上游市场页面、上游 v2.0.7 的精确基点、具体差异、贡献方向及维护流程；清楚区分已核验事实、尚未发送的上游沟通草稿和待完成的人工验收。
- **回退说明**：补充跨标识切回旧主题，以及同标识恢复原安装包和升级前配置的步骤。

本版继续使用 `theme-butterfly-shell`、`theme-butterfly-shell-setting` 和 `theme-butterfly-shell-configmap`，没有新增主题配置字段。ImgNest 是可选集成，未安装或未使用 ImgNest 不影响普通主题使用。

## 安装与升级

1. 备份 Halo 数据与当前主题设置，保留当前版本 ZIP。下载本版 `theme-butterfly-dist.zip`，可使用一同提供的 `.sha256` 与 `.manifest.json` 核对版本和完整性。
2. 全新安装时，通过 **主题管理 → 安装主题** 上传 ZIP，预览后启用 **Butterfly-shell**，填写真实作者用户名，并按需配置菜单和插件。
3. 从 v2.3.4 升级时，在 `theme-butterfly-shell` 的详情页选择 **··· → 升级** 上传本版；无需转换配置，可重载主题配置表单后检查原设置。
4. **从 v2.3.3 及以前的 `theme-butterfly` 迁移时，必须通过“安装主题”安装新主题，保留旧主题；不能在旧标识的“升级”入口上传本版。** 先完成下一节的配置迁移，再切换启用。
5. 使用自定义 CDN 时同步本版完整资源，清理页面与浏览器缓存，确认资源版本参数为 `v=2.3.5`；检查首页、文章、菜单、封面、评论与已安装插件页面。

市场版本、安装包和包内 `theme.yaml` 应统一为 **2.3.5**，版本说明使用本文内容。不要将已发布的 2.3.4 安装包替换为本版内容。

## 从旧标识迁移配置

1. 保留旧主题及原版本 ZIP。在有后台授权的请求中，通过 `GET /apis/api.console.halo.run/v1alpha1/themes/theme-butterfly/json-config` 导出纯 JSON 设置为私密的 `old-theme-config.json`。
2. 安装新主题，暂时保留旧主题启用。对原始备份运行源码中的离线工具：

   ```bash
   node scripts/migrate-theme-identity.cjs old-theme-config.json -o new-theme-config.json
   ```

3. 检查输出，用 `PUT /apis/api.console.halo.run/v1alpha1/themes/theme-butterfly-shell/json-config` 写入转换后的完整 JSON 对象，并用同一路径的 `GET` 回读核对。
4. 预览、启用新主题，核验配置和页面。旧设置、原始备份和旧安装包继续保留，供回退使用。

工具只转换文件中的主题身份与内部资源路径，不连接站点，不覆盖输入或已存在的输出文件。更早版本的顶层页面分组需先完成分组迁移；完整 ConfigMap 备份不能直接作为 `json-config` 接口请求体。格式与详细步骤见[配置迁移说明](https://github.com/biliblihuorong/halo-theme-butterfly/blob/v2.3.5/docs/configuration.md#从旧主题标识迁移到-v234)。

## 回退

**跨标识迁移后：** 在主题管理中选中保留的原 `theme-butterfly` 并启用；原配置未变时无需反向迁移。若旧主题已卸载，安装迁移前实际使用版本的 ZIP；仅当旧配置缺失或变化时，向旧标识的 `json-config` 接口写回原始 `old-theme-config.json`，再回读核对。不要将新主题配置写回旧主题。

**从 v2.3.4 升级后：** 先启用另一个已验证的备用主题，对 `theme-butterfly-shell` 选择普通“卸载”并保留配置，安装原 v2.3.4 ZIP，再通过新标识的 `json-config` 接口恢复升级前备份，回读并预览确认后启用。不要选择“重置”或“卸载并删除配置”；只装旧包不会自动还原过去的设置值。

两种情况都需恢复原版本的自定义 CDN 资源并清理缓存，检查页面与评论。主题回退不代替 Halo、插件及业务数据各自的恢复流程；完整说明见[回退步骤](https://github.com/biliblihuorong/halo-theme-butterfly/blob/v2.3.5/docs/configuration.md#回退到升级或迁移前的版本)。

## 验证与重新提交状态

本版的自动化验证应执行 `pnpm test` 和 `pnpm build-zip`，并记录实际结果、安装包 SHA-256 和源码提交。回归用例包含真实图候选保留、错误标记候选清除及失败回退；自动化通过不表示维护者已经完成人工审查。

**人工验收尚未完成，当前材料不能作为“人工测试已通过”的声明。** 维护者需在待发布制品上逐项填写以下结果：

- [ ] 记录测试人员、日期、安装包 SHA-256、Halo / 插件版本及桌面 / 手机浏览器。
- [ ] 审查 AI 修改的代码与迁移工具；检查全新安装、项目图标、名称和社区身份。
- [ ] 完成 v2.3.4 同标识升级、旧标识配置迁移，以及上述两种实际回退。
- [ ] 核验主要页面、分页、已安装插件页面、深浅色、阅读工具、代码高亮和评论。
- [ ] 使用实际响应式图片插件检查封面候选保留与失败回退，并验证未使用 ImgNest 的正常路径。
- [ ] 在市场使用 2.3.5、同一图标及本文版本说明，补齐真实上游 Issue / PR 链接与处理结果。

完整清单与上游沟通当前状态见[重新提交前的验收记录](https://github.com/biliblihuorong/halo-theme-butterfly/blob/v2.3.5/docs/marketplace.md#重新提交前的验收记录)。历史版本说明中的测试记录只代表对应历史版本，不替代本版人工验收。
