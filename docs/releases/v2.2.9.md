# Butterfly v2.2.9

本版本修复此前确认的 20 类问题，并把本地已有的 2.2.x 定制提交纳入 GitHub 版本线。重点是评论明暗切换、正文可读性、目录和分页、友链说明、旧配置迁移，以及源码与安装包的可核对性。

## 修复清单

| 编号 | 修复 | 新行为 |
| --- | --- | --- |
| 1 | 深色模式评论文字不清晰 | Artalk 实例跟随主题切换，评论正文和输入框同步使用正确颜色 |
| 2 | 主题回调互相覆盖 | 保留多个订阅者；单个订阅者失败不会阻断其他模块 |
| 3 | 友链标题写死为“链接管理” | 页签、首屏和评论标题跟随链接插件的页面标题，缺值时使用“友情链接” |
| 4 | 友链说明默认内容退化、入口不明显 | 恢复原交换规则、隐私链接、本站信息和 7 条解除记录；入口命名为“友链申请说明”，保存字段保持不变 |
| 5 | 移动目录无法展开 | 使用明确的展开 class，并同步按钮的展开状态和目录关联 |
| 6 | 内置 Artalk 打包后丢失导出 | 发布产物保留浏览器 `Artalk.init`，内置资源可正常初始化 |
| 7 | Prism 加载失败后代码不可见 | 请求失败、导出缺失或超时均恢复可阅读的原始代码；高亮仅处理当前正文 |
| 8 | 独立页面滚动报空引用 | 没有目录容器时跳过目录按钮和滚动逻辑 |
| 9 | 标签统计缺少柱状数据 | 按真实图表配置注册柱状图、dataset、transform 和标记组件 |
| 10 | 浏览器存储受限会中断初始化 | 存储失败时继续使用当前页的主题状态；无效模式回退到浅色 |
| 11 | 数字分类、年月归档分页地址错误 | 只替换路径末尾的分页段，保留别名、年月和查询参数；单页不生成分页 |
| 12 | 友链 Artalk 开关无效 | 模板读取 `artalk_enable_links`，关闭后不输出评论区 |
| 13 | 配置迁移漏项或跳过部分配置 | 补齐文章、追番及卡片样式；深度补齐缺失字段，保留已有新值，包括 false 和空字符串；重复执行保持幂等 |
| 14 | canonical 重复、列表页误指首页 | canonical、描述、Open Graph 和 Twitter Card 统一由 Halo 的 HeadProcessor 输出 |
| 15 | 分类列表与图表计数不一致 | 都读取公开模型的 `postCount` |
| 16 | 独立页面封面被忽略 | 优先使用页面设置的封面，缺值时回退首页背景 |
| 17 | 独立页面代码功能配置不完整 | 文章与独立页面共用渲染配置，高亮、复制和折叠使用完整配置 |
| 18 | 脚注链接和 ID 的前缀不一致 | 主题修正当前正文内可唯一匹配的锚点和旧书签，不改写文章数据；保留已有精确匹配和外部链接 |
| 19 | 长期缓存导致更新后继续加载旧资源 | 初始资源使用新版本参数，图表异步包使用内容哈希文件名，字体和 Prism 同步加入版本标识 |
| 20 | 相同版本号对应不同源码和旧安装包 | 统一版本为 2.2.9，完整构建后打包，附带 ZIP SHA-256 和逐文件校验清单 |

另外修复了关闭文章首屏后缺少正文标题、文章目录不遵循侧栏开关、分类图表缺少图例、图表尚未初始化时 resize 报错，以及裸域名 DNS 预解析地址无效等相关边界。

## 与 GitHub v2.1.8 的范围差异

PR 包含此前本地未进入 GitHub 的 7 个提交：Artalk 集成、原生 DOM 替代 jQuery、共享与延迟资源加载、字体与图标子集、页面设置及 Steam / 追番局部导航、友链说明和文档改进。并非仅在 v2.1.8 上修改几个文件。

Font Awesome 使用 Free 6.6.0，Pro 专属图标改用可分发的 solid 图标。新增字体、默认背景和部分通用默认配置保留本地版本的既有选择；已保存的站点配置不会因修改默认值而被替换。新增 Font Awesome 图标仍需检查白名单并重新构建。

## 升级与迁移

1. 备份当前启用的主题包和 **theme-butterfly-configMap**，保留 Artalk 站点名、服务端地址及 pageKey 末尾斜杠设置。
2. 从 Release 下载 **theme-butterfly-dist.zip**，同时下载 `.sha256` 与 `.manifest.json`。使用 ZIP 安装，源码压缩包不能直接作为主题安装包。
3. 若来自旧版顶层 `post / archives / tags / categories / friends / links / bangumis / card` 配置，先在备份上迁移并核对输出：

   ```bash
   pnpm migrate-page-hero -- theme-butterfly-configMap.backup.yaml -o migrated.yaml
   ```

   支持旧 `data.default` 单 JSON 和 Halo 按分组存放 JSON 的 ConfigMap。已有的新字段优先保留；不会把诊断文字写进 YAML。检查后再导入实际环境。

4. 上传新 ZIP，执行“重载主题配置”。确认作者用户名、评论来源、Artalk 地址与站点名、首屏和卡片样式。
5. 清理 CDN 中缓存的 HTML，确认页面请求包含 `v=2.2.9`，图表请求为 `echarts.<内容哈希>.chunk.min.js`。若使用自定义 CDN，也需同步完整的新资源。
6. 检查首页、文章、独立页面、分类、标签、归档和已安装的插件页面。

友链说明入口：**主题设置 → 页面设置 → 友链页 → 友链申请说明**，支持 Markdown / HTML。旧字段 `page_hero.links.footer_content` 保持不变。

## 验证与产物

- 35 项回归测试覆盖主题/评论同步、存储异常、移动目录、独立页面空目录、分页、脚注及迟到的书签、迁移幂等与配置保留、Prism 失败降级，以及实际 ECharts 柱状数据绘制。
- 实际构建产物完成 8 组本机浏览器 fixture 回归，包括手机目录、明暗模式、独立页面代码工具栏、标签与分类图表、数字分页、友链说明、Prism 请求失败和存储禁止场景。Thymeleaf 3.1 / SpringEL 验证源码与压缩片段的配置绑定、评论开关和页面封面回退。
- 完整构建验证内置 Artalk 的浏览器导出、共享渲染配置、内容哈希异步包、主题与 package 版本一致性。
- GitHub Actions 对 PR 执行测试和锁定依赖构建；pnpm 的可选安装脚本策略显式配置；标签发布复用已经校验的 CI 安装包，并附带校验文件。
- `.manifest.json` 记录源码提交、版本、ZIP 哈希及安装包每个文件的哈希，可用于核对线上部署与源码。

该 Release 对应修复 PR 的版本提交；发布不等于将主题安装到 blog.ning.moe。没有替换线上主题，也没有批量修改文章、评论或数据库。脚注修复发生在页面显示时。

## 保持的边界

- 站点自行选择的其他高亮插件与主题 Prism 仍应二选一。
- 插件未安装、作者用户名配置错误或自定义资源地址失效，需要修正对应配置。
- 本版本没有为 Halo 站点新增后台插件或更改其数据结构。
